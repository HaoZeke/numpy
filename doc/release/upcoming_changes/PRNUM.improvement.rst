F2PY defines its C integer types with ``numpy/npy_common.h``
------------------------------------------------------------
Modules generated by F2PY now include ``numpy/npy_common.h`` and define
the F2PY C type names ``signed_char``, ``unsigned_char``,
``unsigned_short``, ``unsigned_long``, ``long_long`` and
``unsigned_long_long`` as aliases of ``npy_byte``, ``npy_ubyte``,
``npy_ushort``, ``npy_ulong``, ``npy_longlong`` and ``npy_ulonglong``
instead of repeating their platform-specific definitions. The names can
still be used in ``callstatement`` and ``callprotoargument`` code of
signature files and in ``.f2py_f2cmap`` files. This fixes building
wrappers with ``integer(kind=-8)`` arguments on 32-bit Windows without
MinGW.
