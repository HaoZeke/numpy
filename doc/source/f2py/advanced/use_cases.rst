Dealing with KIND specifiers
============================

F2PY handles ``<type spec>(kind=<kindselector>)`` declarations only when
``<kindselector>`` is a numeric integer (e.g. 1, 2, 4,...). It does not
accept function calls like ``KIND(..)`` or arbitrary expressions, because
F2PY must resolve the corresponding C type at code-generation time.

To work around this, users can define custom <Fortran type> to <C type>
mappings. For example, if Fortran 90 code contains::

    REAL(kind=KIND(0.0D0)) ...

then create a mapping file containing a Python dictionary::

    {'real': {'KIND(0.0D0)': 'double'}}

Pass this file to F2PY with the ``--f2cmap`` option. By default, F2PY
looks for ``.f2py_f2cmap`` in the current working directory.

More generally, the f2cmap file must contain a dictionary with items::

    <Fortran typespec> : {<selector_expr>:<C type>}

that defines mapping between Fortran type::

    <Fortran typespec>([kind=]<selector_expr>)

and the corresponding <C type>. The <C type> can be one of the following::

    double
    float
    long_double
    char
    signed_char
    unsigned_char
    short
    unsigned_short
    int
    long
    long_long
    unsigned
    complex_float
    complex_double
    complex_long_double
    string

For example, for a Fortran file ``func1.f`` containing:

.. literalinclude:: ./../code/f2cmap_demo.f
    :language: fortran

To map ``int64`` and ``real64`` to valid C data types, create a
``.f2py_f2cmap`` file in the current directory with the following content:

.. code-block:: python

  dict(real=dict(real64='double'), integer=dict(int64='long long'))

Then build the module as usual. F2PY checks for a ``.f2py_f2cmap`` file in the
current directory and uses it to map ``KIND`` specifiers to C data types.

.. code-block:: sh

  f2py -c func1.f -m func1

Alternatively, save the mapping file under any name (e.g. ``mapfile.txt``) and
pass it to F2PY with ``--f2cmap``:

.. code-block:: sh

  f2py -c func1.f -m func1 --f2cmap mapfile.txt

For more information, see F2Py source code ``numpy/f2py/capi_maps.py``.

Character strings
=================

Assumed length character strings
-----------------------------------

In Fortran, assumed-length character string arguments are declared as
``character*(*)`` or ``character(len=*)``; the length is determined by
the actual string argument at runtime. For ``intent(in)`` arguments,
this poses no problem for F2PY. For ``intent(out)`` arguments, however,
F2PY has no size information for allocating output buffers and defaults
to length 0. Depending on how the length is specified, there are
workarounds, as shown below.

When the length of a ``character*(*)`` output argument depends on other
input arguments, the connection can be established in a signature file
or an f2py-comment by adding an extra declaration that specifies the
length in the character selector. For example, consider ``asterisk1.f90``:

  :literal:

by F2PY. The ``f2py_len=`` specification accepts C expressions as
